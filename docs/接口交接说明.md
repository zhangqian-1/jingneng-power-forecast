# 七站总功率预测接口说明

## 1. 调用方式

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/power/forecast` | 提交真实历史数据，缓存就绪后预测未来 96 点 |
| GET | `/api/power/forecast/latest` | 获取最近一次成功预测，不触发新计算 |

服务器地址由部署方提供，默认端口 8000。Compose 默认只允许服务器本机访问，本机用 `127.0.0.1`；其他机器使用配置好的网关或内网地址，不能直接套用下面的“服务器IP”。POST 请求头为 `Content-Type: application/json`，Body 为 UTF-8 JSON。鉴权和 HTTPS 由网关负责，当前应用不验证 Token。

```bash
curl -X POST "http://服务器IP:8000/api/power/forecast" -H "Content-Type: application/json" --data-binary @examples/input_example.json
curl "http://服务器IP:8000/api/power/forecast/latest"
```

在本包根目录运行；Windows PowerShell 使用 `curl.exe`。`@文件路径` 表示调用方将 JSON 文件内容放进请求正文发送，不是把本地路径传给服务器。平台程序也可以直接构造 JSON Body，不必生成文件。

## 2. 输入字段

| 字段 | 类型 | 要求 |
|---|---|---|
| `batchTime` | string | 可省略，默认最后一个 `ts` 的 `YYYYMMDDHHmm`；提供时作为批次标识返回 |
| `intervalMinutes` | integer | 15；省略时默认 15 |
| `historyDays` | integer | 1；省略时默认 1 |
| `data` | array | 必须正好 96 条，代表最近一天实测数据 |
| `data[].ts` | string | `YYYY-MM-DD HH:mm:ss`；连续、不重复、对齐 15 分钟整刻 |
| `data[].stations` | object | 七站完整快照，以清单中的中文场站名为 key |
| `data[].stations[场站名].load_points` | object | 该站功率测点，单位 MW |
| `data[].stations[场站名].weather_points` | object | 该站温湿度测点，单位为摄氏度和 % |

每个时间点共 19 个功率、8 个温度、8 个湿度字段，完整编码见 [测点需求清单](测点需求清单.md)。测点值为 JSON number，缺测可用 `null` 或省略该测点字段，不要混入单位或百分号。保留原始测点编码中的 `.` 和 `:`，不要改成下划线。

每次提交完整七站，不是单站分别提交再由服务凑齐。通常每 15 分钟推送一次最近 96 点；补历史可按天顺序提交。服务不在线训练，也不需要调用方传未来天气、状态或时间特征。

## 3. 历史缓存与缺失处理

- 功率缺失、未传、非数值或非有限值按 0；实测 0 和有限负值保留，不插值、不沿用上一功率。遗漏整个站也会使该站功率按零，所以调用方必须保证快照完整。
- 温湿度只沿用该测点已经收到的过去真实值，不用未来值回填。某点没有任何历史观测时，需要更早真实历史或继续累计，不能假定填 0 即可。
- 每次输入与已有历史按时间戳合并。重复时间的功率使用最新快照，最新缺失则按零；天气保留该时刻最新非空观测，再向后填充，不重复累计。
- 必须有 **672 个连续且温湿度可构造的历史点** 才能预测。整条时间记录缺失会打断连续性，不自动造记录。
- 不足时返回 HTTP `409`，本次数据仍缓存；调用方继续按时间提交后续真实数据，不要把它当成服务崩溃而清缓存。
- 容器内缓存为 `/app/runtime/history_7station_2025_v1.csv`，Compose 默认保存到宿主机 `compose.yaml` 同目录下的 `runtime`，可通过 `.env` 调整宿主机目录。最多保留 768 个时间点（8 天）及历史上下文，旧十站缓存不可混用。
- 请求末点早于已有缓存末点时返回 `400`。补启动历史要从最早一天开始顺序提交，历史测试须另起空缓存服务，不覆盖生产缓存。

## 4. 成功输出

HTTP `200`，JSON 字段如下：

| 字段 | 类型 | 含义 |
|---|---|---|
| `code` / `msg` | integer / string | 成功为 200 / 返回说明 |
| `batchTime` | string | 请求批次标识 |
| `generatedAt` | string | 本次执行生成时间，不是预测目标时间 |
| `model` | string | 当前为 `StationAttentionFusion_TrendDetail_7station_2025_v1` |
| `accuracyBasis` | string | 历史准确率参考的统计依据 |
| `testRMSE` | float | 固定的离线测试集 RMSE，单位 MW |
| `inputQuality` | object | 本次提交数据的缺失值统计 |
| `historyCache` | object | 缓存状态；`ready`、`continuousPoints`、`requiredPoints` 表示就绪情况 |
| `data` | array | 未来 96 个预测点 |
| `data[].predictedTime` | string | 目标时间，`YYYYMMDDHHmm` |
| `data[].timeSeries` | integer | 序号 1 到 96 |
| `data[].predictedPower` | float | 七站总功率预测，MW，保留四位小数 |
| `data[].accuracy` | string | 两位小数加百分号的离线历史参考 |

预测从输入最大 `ts` 后 15 分钟开始，连续 96 点；`batchTime` 不决定起报时间。返回的是一个七站总功率序列，不是 19 个测点或 7 个场站分别预测。

**`accuracy` 不是当次预测的真实准确率。** 它是 `clip(100 - 对应预测步长的离线 MAPE, 0, 100)`，模型不变时各步参考值固定。当前预测的真实误差只能等目标时间的实测值到达后再算。

`inputQuality` 统计本次提交，`historyCache.cacheFillQuality` 统计缓存合并处理，计数范围不同。`latest` 可能保留较早的成功结果；调用方需检查 `generatedAt` 和 `predictedTime`，不能只看到 HTTP 200 就认为是本次新结果。

## 5. 错误与处理

| HTTP 状态码 | 含义及处理 |
|---|---|
| 400 | JSON、字段、测点或时间错误，或提交了过旧批次；按 `msg` 修正 |
| 404 | 地址错误，或 `latest` 尚无成功结果；检查路径并先提交历史数据 |
| 409 | 连续可用历史不足；数据已缓存，继续补真实历史 |
| 413 | Body 超过 50 MiB；检查是否误传了超出一天的数据 |
| 422 | 模型输入或数据内容不符合要求；查看 `msg` 并核对数据 |
| 500 | 模型加载、预测或结果读取内部错误；保留请求批次及响应，交运维查日志 |

错误响应仍为 JSON，含 `code`、`msg`、空数组 `data`。`409` 额外含 `historyCache`，可查看当前连续点数与要求点数。接口没有专用 `/health` 路由；Compose 用现有 `latest` 接口检查服务是否响应，健康不等于历史就绪。新增 Compose 不改变请求、响应或预测规则。

## 6. 完整 JSON 样例

| 文件 | 时间与前提 |
|---|---|
| [成功输入](../examples/input_example.json) | 2025-10-19 00:00 至 23:45，每条包含七站 35 个测点字段 |
| [成功输出](../examples/output_example.json) | 历史已预热后，预测 2025-10-20 00:00 至 23:45，共 96 点 |
| [冷启动输入](../examples/input_not_ready_409.json) | 2025-10-06 的 96 点，向空缓存首次提交 |
| [冷启动输出](../examples/output_not_ready_409.json) | 对应上行输入：HTTP 409，已有 96 点，要求 672 点 |

成功样例来自按日期顺序回放 2025-10-06 至 10-19 的真实数据，不能只传成功输入文件一次就复现成功输出；两份输出也不是同一个输入的配对记录。完整测试步骤见 [部署说明](Docker部署运行说明.md)。

样例里的 `generatedAt` 和 `cacheFile` 保留当时测试时间、测试机路径，不需要调用方照抄为服务器配置。运行时生成时间和缓存路径会随环境变化，不同计算环境可能有少量浮点差异。
