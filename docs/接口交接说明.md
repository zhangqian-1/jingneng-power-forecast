# 全站总功率预测接口交接说明

## 1. 服务定位

本服务是十个场站全站总功率预测服务。外部系统每 15 分钟提交最近一天的真实数据，服务端缓存历史数据，累计最近 7 天 672 个连续点后，调用离线训练好的模型预测未来一天 96 个点。

本服务不在线训练，不读取生产服务器上的原始 CSV，不使用 Gurobi，不做单场站独立预测，也不返回机组调度、成本或碳排放结果。

## 2. 接口地址

当前生产包提供以下接口。服务器地址和端口由部署环境确定，默认端口为 8000。

| 目的 | 方法 | 路径 |
|---|---|---|
| 提交最近一天真实数据并尝试预测 | POST | /api/power/forecast |
| 获取最近一次成功预测结果 | GET | /api/power/forecast/latest |

POST 请求头为 Content-Type: application/json。

调用地址示例：http://服务器IP:8000/api/power/forecast

## 3. 请求格式

| 顶层字段 | 类型 | 要求 |
|---|---|---|
| batchTime | string | 本批次时间标识，建议使用最后一个 ts 的 YYYYMMDDHHmm |
| intervalMinutes | integer | 必须为 15 |
| historyDays | integer | 必须为 1，表示本次提交最近一天 |
| data | array | 必须包含 96 个连续时间点 |

每个 data 元素包含 ts 与 stations；每个场站包含 load_points 和 weather_points。完整真实输入样例见 examples/input_example.json，其中包含 96 个时间点、10 个场站、29 个功率点和 23 个温湿度点。测点全集见 docs/测点需求清单.md。

curl 调用示例：

    curl -X POST "http://服务器IP:8000/api/power/forecast" -H "Content-Type: application/json" --data-binary @examples/input_example.json

## 4. 请求数据处理

处理流程：

    校验 JSON 和时间序列
    → 十个场站的功率测点按时间点求和
    → 温湿度测点按规则补齐并构造特征
    → 与 runtime/real_history_cache.csv 合并、按时间戳去重
    → 保留最近连续 672 点作为模型输入
    → 调用离线模型预测未来 96 点
    → 返回 JSON

规则：

- 每次请求必须是最近一天 96 个连续点，间隔 15 分钟。
- 重复提交同一时间戳不会重复累计，服务按时间合并。
- 空值、未传测点和非数字值使用缓存中该测点上一时刻的真实值。
- 数字 0 是有效值，不能被当作缺失值替换。
- 不插值、不做低负荷修复、不改写异常值、不生成虚拟数据。
- 某测点在可用历史中从未出现真实值时，无法完成补齐，接口返回错误。

## 5. 响应格式

成功时 HTTP 状态码为 200，data 固定返回未来 96 个预测点。

| 字段 | 类型 | 说明 |
|---|---|---|
| code | integer | 业务状态码，成功为 200 |
| msg | string | 返回说明 |
| batchTime | string | 对应请求批次标识 |
| generatedAt | string | 服务生成结果的时间 |
| model | string | 当前加载的模型名称 |
| accuracyBasis | string | 准确率估计的依据 |
| testRMSE | float | 离线测试集 RMSE，单位 MW |
| inputQuality | object | 本次输入缺失值统计 |
| historyCache | object | 历史缓存状态 |
| data | array | 96 个预测结果 |

每个预测结果包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| predictedTime | string | 预测目标时间，格式 YYYYMMDDHHmm |
| timeSeries | integer | 预测序号，范围 1 到 96 |
| predictedPower | float | 全站总功率预测值，单位 MW |
| accuracy | string | 预计准确率，例如 96.42% |

accuracy 是根据离线测试集、按预测步长统计的历史误差估计值，不是未来真实准确率。等预测目标时间到达并获得真实值后，才能计算本次预测的实际误差。

成功响应完整样例见 examples/output_example.json。

## 6. 缓存不足响应

首次部署或缓存历史不足 672 个连续点时，接口返回 HTTP 409。这表示数据尚未准备完成，不表示服务崩溃；本次提交的数据仍会保存。

示例见 examples/output_not_ready_409.json。达到 672 个连续点后，下一次请求返回 HTTP 200 和 96 个预测点。

## 7. 错误码

| HTTP 状态码 | 含义 |
|---|---|
| 200 | 预测成功 |
| 400 | JSON 格式、字段或时间序列错误 |
| 404 | 路径错误，或尚未产生最新预测结果 |
| 409 | 历史缓存不足 672 个连续点 |
| 413 | 请求体超过服务限制 |
| 422 | 模型输入或数据内容不符合要求 |
| 500 | 模型加载或预测内部错误 |

错误响应仍为 JSON，data 为空数组；409 响应额外包含 historyCache 当前进度。

## 8. 当前边界

- 当前服务地址是 /api/power/forecast，不是其他项目的 FluxCast 调度接口。
- 当前服务没有用户鉴权和 HTTPS，正式环境由网关或部署平台负责。
- 当前服务没有专用 /health 路由；运维可通过启动日志和接口响应检查服务状态。
