# 全站总功率预测服务上线验收说明

## 1. 验收目标

验证生产镜像能够：

1. 正常加载离线训练好的模型；
2. 接收十个场站的真实 JSON 数据；
3. 缓存并拼接历史数据；
4. 缓存达到 672 个连续点后完成预测；
5. 返回未来 96 个预测点；
6. 通过最新结果接口读取结果。

## 2. 静态检查

在生产部署包根目录执行：

    py -3.11 check_config.py

检查活动模型配置、NHITS、PatchTST、StationAttentionHF、模型文件 SHA-256、输入长度 672、输出长度 96 和接口路径。检查应显示通过，不能有模型文件缺失、哈希不一致或接口路径缺失。

## 3. 接口验收

启动容器后，使用私有测试资料中的真实十场站 CSV 生成请求：

    python tests/build_real_test_payloads.py --raw-dir tests/real_data_raw --output-dir tests/fixtures/real_data_daily

连续调用 7 个每日请求：

    python tests/run_api_test.py --base-url http://127.0.0.1:8000 --fixture-dir tests/fixtures/real_data_daily

## 4. 预期结果

| 请求 | 缓存连续点数 | 预期 HTTP 状态码 |
|---|---:|---:|
| day_01 | 96 | 409 |
| day_02 | 192 | 409 |
| day_03 | 288 | 409 |
| day_04 | 384 | 409 |
| day_05 | 480 | 409 |
| day_06 | 576 | 409 |
| day_07 | 672 | 200 |

第 7 次成功响应必须满足：

- data 是数组，长度为 96；
- historyCache.ready 为 true；
- historyCache.continuousPoints 为 672；
- 每个 predictedPower 是数值；
- 每个预测点包含 predictedTime、timeSeries、predictedPower、accuracy。

随后调用：

    curl http://127.0.0.1:8000/api/power/forecast/latest

应返回 HTTP 200 和 96 个预测点。

## 5. 业务规则验收

- [ ] 十个场站均可出现在输入 JSON 中。
- [ ] 29 个功率测点参与每个时间点的总功率求和。
- [ ] 23 个温湿度测点按测点清单传输。
- [ ] 功率数值 0 被保留，不被当作缺失。
- [ ] 空值和非数字值按上一真实值规则处理。
- [ ] 输入不包含随机数据、插值数据或虚拟数据。
- [ ] 容器重启后 runtime 挂载目录中的历史缓存仍然存在。
- [ ] 成功响应返回 96 个预测点。
- [ ] accuracy 被理解为历史误差估计，不被当作未来已验证准确率。

GitHub Actions 或本机测试通过，只能说明该测试环境中的镜像和接口链路正常。正式上线前仍需在目标服务器实际启动容器，并确认目标 CPU 架构、依赖安装、模型加载时间和预测耗时。
